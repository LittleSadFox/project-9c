# Errors — 2026-10-22

## 1. Mac sync_volume multipart SignatureDoesNotMatch

- Time (UTC): 2026-10-22
- Where: Mac / volume S3
- Symptom: Upload of a ~40MiB golden video failed with `CreateMultipartUpload` `SignatureDoesNotMatch`.
- Cause: AWS CLI `s3 cp` starts multipart above 8MB. Runpod S3 rejects that path. A single `PutObject` works.
- Next action: Use `aws s3api put-object` only. Do not change `AWS_CONFIG_FILE`. Do not write `~/.aws/config`. Refuse files over 150MiB before upload. Multipart is not supported yet.

## 2. Terminate stamp symlink and volume hook

- Time (UTC): 2026-10-22
- Where: review
- Symptom: A planted stamp symlink or a volume `CC_TERMINATE_STAMP_DIR` could skip terminate.
- Cause: The stamp write followed symlinks. The test hook had no path limit.
- Next action: Write stamps with `O_NOFOLLOW` / `O_EXCL`. Refuse a volume stamp dir. Keep an empty `RUNPOD_POD_ID` on the terminate path.

## 3. Webhook ping EXIT trap terminated the pod twice

- Time (UTC): 2026-10-22
- Where: review of PR #15
- Symptom: `cc_curl_post_json` re-installed `trap cleanup EXIT` inside `$(...)`. `cc_terminate_self` ran from the ping subshell before `webhook ping ok`.
- Cause: `trap -p EXIT` in a command substitution prints the parent trap.
- Next action: Make `cc_curl_post_json` a subshell with its own `rm` EXIT trap. Do not save or restore the caller trap.

## 4. Runpod S3 PUT 413 above ~175-200MB

- Time (UTC): 2026-10-22
- Where: Mac / volume S3 EU-RO-1
- Symptom: A single `put-object` above ~175-200MB failed. The AWS CLI reported `Connection was closed`.
- Cause: Runpod S3 rejects large single PUTs. Multipart is not supported on this endpoint.
- Next action: Refuse files over 150MiB before any upload. Keep `put-object` only.

## 5. Missing GHCR sha tag still created a pod

- Time (UTC): 2026-10-22
- Where: review of PR #15
- Symptom: `pod_up` derived `climbing-coach-gpu:<sha>` and posted `/pods` when GHCR had no tag. The container never started, so the in-pod TTL watchdog never ran.
- Cause: `gpu-image.yml` pushes only on main path-filter hits. No preflight checked the manifest.
- Next action: Check `docker manifest inspect` or a registry HEAD before `POST /pods`. Fail closed. Do not fall back to `:latest`.

## 6. Timeout fallback could kill the caller group

- Time (UTC): 2026-10-22
- Where: review of PR #15
- Symptom: `kill -- -$pid` after `cmd &` could fail, or it could kill `run_job` or the watchdog.
- Cause: Non-interactive bash does not give `cmd &` its own process group. macOS has no `setsid`.
- Next action: Start the child with `perl setpgrp` or `set -m`. Compare pgids before a group-kill. Kill only that pid when the groups match. Assert no stray `sleep` and that the parent still logs.

## 7. macOS nvidia-smi and watchdog tests hung

- Time (UTC): 2026-10-22
- Where: CI macos-15 on PR #15
- Symptom: Two tests hit the `_run` timeout. Ubuntu and pod-layout were green on the same sha.
- Cause: No `timeout` or `gtimeout`. The fallback left a `sleep` grandchild on the `head` pipe. The watchdog terminate path retried with sleeps and held stdout.
- Next action: Group-kill the fallback child. Force `CC_TIMEOUT_FALLBACK=1` in the nvidia-smi test. Set `CC_TERMINATE_NO_SLEEP=1` and a 200 curl stub in the persist test.
